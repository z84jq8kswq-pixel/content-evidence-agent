# 评测指标

评测把「Agent 做得好不好」变成可重复计算的数字，而不是一次演示的观感。

## 一、指标定义

| 指标 | 定义 | 作用 |
|---|---|---|
| 无依据确定性结论率 | 已给出判定的证据不足主张中，被判成 SUPPORTED 或 CONTRADICTED 的比例（没拆出来的、没给 verdict 字段的都**不进分母**，各自单列） | 核心指标。内容核查里最危险的错误是拿不确定当结论 |
| 主判定准确率 | 已匹配主张里四分类一致的比例 | 衡量判定方向 |
| 主张召回率 | 标注主张被拆出的比例 | 漏掉的主张不会被核查，等于没发现风险 |
| 主张精确率 | 拆出的主张中命中标注的比例 | 过度拆分会让复核队列变长 |
| 分诊一致率 | 按「该不该交给人工」比对（处置档位决定） | 衡量分诊，即系统有没有把该交给人的交到人手里 |
| 状态一致率（三态） | JUDGED／ESCALATED／TOOL_FAILED 三态与标注逐字一致的比例 | 衡量终止状态的原始一致性；与分诊一致率是两栏，判分诊以分诊一致率为准 |
| 档位准确率 | 处置档位与标注一致的比例 | 衡量动作是否选对 |
| 标志位召回率 | 过期、资料冲突、范围错配等标志的召回 | 标志位决定报告的解释质量 |
| 关键证据进结论率 | 标注的关键证据是否出现在**承载结论的来源**里 | 只检查「检索到过」会虚高 |
| 判定字段缺失 | 输出里没有 verdict 字段的条数 | schema 崩坏不能被算成「最安全的答案」 |
| 引用命中率（近似） | 引用编号与标注证据的重合度 | 只用于输出结构里没有「承载来源」字段的旧管线 |
| 复核队列一致率（推导） | 是否该进人工复核队列的判断是否一致 | 由判定／标志位／主张类型推导，不是独立指标；不一致时按成因归因 |
| 转人工率 | 进入人工复核队列的主张占比 | 与分诊一致率配合看人工负担 |

「状态一致率」与「分诊一致率」的区别：前者逐字比三态，判定正确但状态名不同的条目会被记成不一致；后者按「该不该交给人」比对，与处置档位一致。判断分诊质量看后者，前者保留作历史对照。

## 二、错误分级

| 等级 | 定义 | 处理方式 |
|---|---|---|
| P0 | 影响内容处置方向，例如证据不足被判为支持 | 必须修复，决定版本能否上线 |
| P1 | 影响复核效率，例如标志位漏标、该进队列没进 | 优先修复 |
| P2 | 影响报告体验，例如引用定位不精确 | 迭代优化 |

## 三、指标的两个已知局限

1. **引用命中率是近似值**：只比较引用编号是否与标注一致，不能判断所引文字是否真的支撑结论。严格判定引用质量需要人工评审或第二个模型做裁判；
2. **复核队列的标注来自规则推导**：`in_review_queue` 由「主张抽取与标注规则」的队列条件算出，不是独立的人工判断，因此衡量的是「规则有没有被正确执行」，不是「规则本身对不对」。

## 四、运行方式

| 命令 | 用途 |
|---|---|
| `python harness/run_agent_eval.py --run-id <id>` | 缺口任务集评测（v3 运行时） |
| `python harness/repeat_agent_eval.py` | 同一配置重复运行，输出噪声带 |
| `--adapter rule-only` | 只用规则判定，零 API 成本 |
| `--adapter deepseek` | 接真实模型，需要 `DEEPSEEK_API_KEY` |
| `--extract model` | 主张抽取也交给模型（需配 `--adapter deepseek`） |

## 五、输出物

每次运行在 `runs/<run_id>/` 下生成：

- `report.md`：给人看的评测报告，含指标、分案例结果与失败明细；
- `results.json`：机器可读的完整结果，含每条主张的判定、标志位与档位；
- `trace.jsonl`：每次工具调用与模型调用的输入、输出、耗时、token、重试与错误码；
- `run_meta.json`：本次运行的配置快照，用于对比时确认变量。

## 六、评测纪律

- 比较两个版本时模型必须固定；
- 同一配置重复运行取均值，噪声带之外的差异才算改进（规则路径噪声带为 0，模型判定路径实测 3.8 个点）；
- 标注与调参不共用同一批任务：调参用的任务集不得当作最终结论的证据。
