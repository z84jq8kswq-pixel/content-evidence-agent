# 检索架构依据

本文档记录检索架构的外部依据与核实程度。依据本身也要可核，因此每条都标注来源与核实状态。

## 一、结论

**召回／排序两阶段是范式，落地形态是多路召回 → 融合 → 粗排 → 精排。** 按主体过滤只是其中一路，不能当唯一入口。

## 三、相关度阈值

现状实测（26 条标注主张，当前检索函数取 Top-5，比较「标注关键证据」与「顺带召回的非关键材料」的得分分布）：

| 观测 | 数值 |
|---|---|
| 关键证据被召回的条数 | 20 / 26 |
| 关键证据的最低分／中位 | 1.00 / 7.20 |
| 非关键材料的最高分／中位 | 10.49 / 4.20 |
| 关键与非关键能分开的条数 | 16 / 20 |

结论：**一个全局相关度下限在当前打分函数下不可分**（关键证据最低分为 1.00，低于非关键材料的最高分 10.49）。因此顺序是**先改打分函数，再定阈值**。要改三处：

1. **长度归一化**：当前是词频累加，长文档天然高分；
2. **实体权重**：命中主张主体名的材料才算强相关，当前没有这个信号；
3. **阈值的作用位置**：不是用来过滤召回结果，而是决定**证据是否充分**（这份材料够不够格支撑一个结论），不是「要不要把它捞回来」。

定阈值的方法：把关键证据分与非关键分画成分布看可分性，用可分的那部分定切点，再验证加上阈值后有多少结论翻转、翻的是不是该翻的。

## 四、多路召回（四路）

| 路 | 召回什么 | 为什么需要 |
|---|---|---|
| 1 | 主体 + 指标的结构化事实（精确查询） | 拿到可被规则比对的数值，最便宜最硬 |
| 2 | 主体名／别名的文档检索 | 厂商规格页、检测报告这类正文资料 |
| 3 | 指标 + 数值的跨主体检索 | 捞法规、标准、行业名录这类上位公共依据——它们不属于任何产品，只按主体过滤会全部漏掉 |
| 4 | 站内同实体的其他说法 | 交叉验证：同一商品的其他笔记怎么说 |

融合去重 → 相关度下限 →（有模型时）精排与判定。这样「漏关键内容」的风险被拆到「某一路没召回」，而每一路的召回率都能单独测。

## 五、离线可复现

检索为纯标准库实现：中文按二元组切分，英文与数字按整词，标题权重加倍。不引入向量库或嵌入模型，理由是评测要能离线复跑、结果要能逐步复现。语义检索会同时破坏这两点。真实产品路径上的联网检索属于工具层的独立能力（第四个工具：联网检索 + 结果快照），与离线评测路径分开。
