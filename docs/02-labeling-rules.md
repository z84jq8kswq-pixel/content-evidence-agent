# 02 标注规则

规则的目标是让两个人独立标注后能得到基本一致的结果。这份文档也是后续 Prompt 约束和评测口径的来源。

## 一、核查单元

核查单元是**可独立判定的最小事实性主张**。一条内容拆成几条主张，遵循下面的规则。

1. 一条主张只包含一个可验证的核心判断。出现"而且""并且""同时"时，通常需要拆开。
2. 数值与限定条件属于同一条主张。条件被省略不是另一条主张，而是该主张的标志位。
3. 因果表述拆成两部分：事实部分和因果关系。事实可以判定，因果关系在没有对照实验时标为证据不足。
4. 比较型主张需要两边数据齐全才能判定。只给出一边对比数据时标为证据不足。

不核查的内容：纯主观偏好（"我觉得手感不错"）、修辞夸张（"好用到哭"）、无事实指向的口号（"年轻人的第一台"）。

以下内容同样不作为主张：作者个人的使用习惯、作息和主观体验，例如"我每天通勤两小时"。这类内容无法从外部资料验证，纳入核查只会污染报告。

## 二、主张类型

| 类型 | 说明 | 例子 |
|---|---|---|
| 数值型 | 具体数字，可容差比较 | 续航 40 小时 |
| 范围型 | 涉及型号、批次、地域范围 | 全系支持无线充电 |
| 排他型 | 唯一、第一、独家 | 行业第一、独家专利 |
| 认证型 | 资质、检测、认证 | 通过抗菌认证 |
| 健康安全型 | 功效、成分、安全 | 4 周体能改善 |
| 因果型 | 把相关说成因果 | 泵压更高所以更浓 |
| 时间型 | 与特定时间点绑定 | 现在到手价 899 |

## 三、主判定

每条主张只给一个主判定。

| 判定 | 定义 | 触发条件 |
|---|---|---|
| SUPPORTED 支持 | 存在有效证据支持该主张 | 至少一条 E1/E2 证据直接支持，且无相反证据 |
| PARTIAL 部分支持 | 主张本身有真实依据，但遗漏了会改变理解的条件或范围 | 证据成立但条件、范围、浓度、档位等被省略 |
| CONTRADICTED 冲突 | 存在有效证据与主张相反 | 至少一条 E1/E2 证据直接否定主张 |
| INSUFFICIENT 证据不足 | 现有资料无法支持也无法否定 | 只有营销来源、资料互相矛盾、资料过期、范围错配 |

判定优先级：先看是否存在有效证据，再看证据是否直接指向该主张，最后才考虑证据等级。**不允许在证据不足时给 SUPPORTED 或 CONTRADICTED。**

特别注意：检索不到相关记录不等于反证，只能得到 INSUFFICIENT。

## 四、标志位

标志位可以多选，用于说明为什么得到该判定，也用于单独统计。

| 标志 | 含义 |
|---|---|
| STALE | 依据的资料已过期或版本不符 |
| SOURCE_CONFLICT | 有效资料之间互相矛盾 |
| SCOPE_MISMATCH | 资料覆盖的范围与主张不一致，例如型号、批次、部位 |
| OMITTED_CONDITION | 主张省略了影响结论的条件 |
| UNIT_MISMATCH | 单位或统计口径不一致 |
| LOW_SOURCE_QUALITY | 仅存在营销或不可溯源来源 |

## 五、证据等级

| 等级 | 定义 | 例子 |
|---|---|---|
| E1 | 一手可核验来源 | 官方规格页、说明书、认证机构登记信息、公开政策文本 |
| E2 | 权威第三方 | 检测机构报告、行业标准、专业文献、主流媒体调查 |
| E3 | 用户实测或匿名来源 | 开箱实测、测评博主、论坛反馈 |
| E4 | 营销与不可溯源来源 | 品牌自述、直播口播、无出处的"数据显示" |

### 来源身份与门槛（2026-10-14 起）

分级的主判据是**门槛**：取证时只问"这条来源能不能单独支撑一个结论"，而不是把几个维度加权求和再比一条分数线。加权求和做不到这件事——在求和口径下"取样方式不明但有认可资质"是 0.95、"厂商送检"是 0.80，两个都能越过 0.60 那条线，"送检样与市售样不是同一批"这条行业共识就等于没写。

| 来源身份 | 门槛 | 门槛说明 |
|---|---|---|
| 监管机构 | 通过 | 监管公开信息 |
| 平台机构 | 通过 | 平台规则文本 |
| 厂商自述 | 通过（厂商送检不通过） | 厂商标称可作为"厂商是否这样标称"的依据 |
| 独立第三方 | 取样为厂商送检则不通过；取样不明但有认可资质则通过 | 送检样与市售品不是同一批 |
| 用户自述 | 不通过 | 用户内容不能单独支撑结论 |
| 未知 | 不通过 | 来源身份不可核 |

取样方式与资质只在**适用的身份**上计分：独立第三方的取样方式（市场随机购买 +0.10／厂商送检 -0.15）与认可资质（+0.10）；厂商自述只在厂商送检时扣分。给监管公开库、平台规则、用户内容标注取样方式与资质属于记录性字段，不计分——给它们加减分是假精度，分数变了而"够不够格"的结论不变。

门槛通过与否还决定另一件事：**依据只有厂商自述时不能触发对外动作**（见 `17-disposition.md` 的 R13）。

使用规则：

- E4 不能单独支撑 SUPPORTED。
- E3 可以支撑 SUPPORTED，但报告需要标注证据强度为中等。
- E1 与 E2 冲突时标 SOURCE_CONFLICT 并进入人工复核。
- 同一结论有两条以上独立来源时，报告标注证据强度为高。

## 六、时效规则

资料是否过期按品类判断，超过下表时限的视为 STALE。

| 品类 | 有效期 |
|---|---|
| 数码与家电规格 | 12 个月 |
| 食品与保健品 | 6 个月 |
| 护肤与美妆成分配方 | 18 个月 |
| 价格与促销 | 7 天 |
| 认证与资质 | 以证书标注的有效期为准，过期即 STALE |

资料过期只影响它作为证据的有效性。除非有现版本资料明确否定该主张，否则过期资料导致的结果是 INSUFFICIENT 加 STALE，而不是 CONTRADICTED。

## 七、数值与范围规则

数值容差默认 ±5%，单位换算后比较。超出容差才判为冲突。

范围型主张按最窄范围判定。例如"全系支持"只要有任一型号不支持，即为 CONTRADICTED 加 SCOPE_MISMATCH。

限定条件规则：主张省略了在资料中出现且会改变结论的条件时，判为 PARTIAL 加 OMITTED_CONDITION。判断关键是该条件会不会影响用户的理解，而不是条件是否存在于资料中。

条件已经写在内容里的，不算省略。例如内容写"关闭降噪时续航 40 小时"，资料也写"关闭降噪 40 小时、开启降噪 28 小时"，该主张判 SUPPORTED；只有内容写"续航 40 小时"而没写条件时，才判 PARTIAL。

这条规则是第一次用真实模型跑评测集时补上的。当时 EV-001 标 SUPPORTED、EV-025 标 PARTIAL，但两条内容的表述方式其实相同，属于标注与规则不一致，由模型输出暴露出来。

## 八、人工复核队列规则

进入复核队列的条件：

- 判定为 CONTRADICTED
- 判定为 PARTIAL
- 带有 SOURCE_CONFLICT 或 STALE 标志
- 判定为 INSUFFICIENT，且属于数值、认证、健康安全或排他型主张

不进队列的 INSUFFICIENT 只在报告中标明"证据不足"，不阻塞流程。

## 九、标注流程与一致性

30 条任务由两人独立标注，分歧项进入仲裁。一致性用 Cohen's kappa 衡量，主判定 kappa 低于 0.7 时说明规则仍有歧义，需要先改规则再评测。

标注顺序：先拆主张，再逐条判主判定，最后补标志位。不允许先看判定再倒推主张。

## 十、常见标注错误

1. 把限定条件当成独立主张，导致一条主张被拆成两条。
2. 资料过期就判为 CONTRADICTED，混淆了"证据失效"和"证据反对"。
3. 资料之间互相矛盾时直接取更权威的一方，忽略了应标记为冲突待复核。
4. 把营销来源当作有效证据，忽略 E4 不能单独支撑结论。
5. 用户实测与官方参数冲突时直接采信官方，忽略了可能是版本或批次差异。

## 十一、错误分级

| 等级 | 定义 | 例子 |
|---|---|---|
| P0 | 影响内容处置方向 | 证据不足被判为支持；冲突被判为支持 |
| P1 | 影响复核效率 | 主判定方向正确但标志位缺失；应进队列但未进 |
| P2 | 影响报告体验 | 引用定位不精确；说明文字冗长 |

评测报告的结论以 P0 数量为首要指标，P1 次之。

## 容差表（判定与标注共用同一把尺）

容差定义「多大的数值差异算不一致」。判定层与标注必须用同一张表，否则模型和标注各用一套、指标就没有意义。
当前数值（**手设先验，待数据校准**，依据与敏感性分析见 `22-harm-and-tolerance.md`）：

| 类别 | 指标 | 容差 | 依据来源 |
|---|---|---:|---|
| 标称型 | 容量、额定能量、快充功率、通量、浓度、含铁量 | 5% | 产品标准里的允许偏差（待逐条落实出处） |
| 测量型 | 续航、亮度、耗时、降噪续航、滤芯寿命 | 20% | 同型号多次实测的离散度（待实测数据；暂用经验值） |
| 比例型 | 废水比（归一成 第一项/第二项） | 10% | 档位边界，不是百分比 |
| 兜底 | 其余 | 10% | 无依据，仅为兜底 |

两条纪律：

1. **不能跨口径用容差**：厂商标称与负载实测不可比（判 NOT_COMPARABLE），不是容差问题；
2. **主张数值与来源数值比对的容差是 10%**（`RELATIVE_CONFLICT_TOLERANCE`），与来源之间的冲突容差是两回事。

收紧的代价已实测：对比容差从 10% 收到 5%，26 条主张里有 3 条从 SUPPORTED 翻成 CONTRADICTED（都是标称与实测差 6–8% 的正常偏差）。所以**只压到了「不能太紧」这一侧**，松开那一侧还缺案例。
