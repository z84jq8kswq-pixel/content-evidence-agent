# 23 检索架构：行业依据与阈值定法

> 记录时间：2026-10-14　|　缘起：用户问「两段式对不对、别家怎么做、从主体过滤会不会漏关键内容」。
> 每条依据都标了核实程度——**依据本身也要可核**，这是这份文档存在的理由。
> 来源可信度规则：优先一手论文与官方技术博客；**知乎等社区文章不作为依据**（2026-10-14 用户要求）。

## 一、结论

**召回／排序两阶段是范式，落地形态是多路召回 → 融合 → 粗排 → 精排。**
按主体过滤只是其中一路，不能当唯一入口。

## 三、相关度阈值：26 条主张上的实测

方法：对 26 条标注主张，用当前检索函数取 Top-5，比较「标注里的关键证据」与「顺带召回的非关键材料」的得分分布。

| 观测 | 数值 |
|---|---|
| 关键证据被召回的条数 | 20 / 26 |
| 关键证据的最低分 / 中位 | 1.00 / 7.20 |
| 非关键材料的最高分 / 中位 | 10.49 / 4.20 |
| 关键与非关键能分开的条数 | 16 / 20 |

**结论：一个全局相关度下限在当前打分函数下不可分**（关键证据最低 1.00 < 非关键最高 10.49）。
所以顺序是**先改打分函数，再定阈值**。要改三处：

1. **长度归一化**：现在是词频累加，长文档天然高分（GAP-017/019 那种长文占便宜）；
2. **实体权重**：命中主张主体名的材料才该算强相关，现在完全没有这个信号；
3. **阈值的作用位置**：不是用来过滤召回结果，而是决定**证据是否充分**（sufficiency）——也就是「这份材料够不够格支撑一个结论」，而不是「要不要把它捞回来」。

阈值怎么定（方法而非数字）：把「关键证据分」与「非关键分」画成分布，看可分性（现在 16/20 可分）；用可分的那部分定切点；再验证加上阈值后 26 条有多少结论翻转、翻的是不是该翻的（GAP-001、GAP-004 那两个已知缺陷应该被修掉）。26 条不足以定精确数字，但足以判断当前打分有没有可分性——目前结论是没有。

## 四、多路召回的落地建议（四路）

| 路 | 召回什么 | 为什么需要它 |
|---|---|---|
| 1 | 主体 + 指标的结构化事实（精确查询） | 能拿到可被规则比对的数值，最便宜最硬 |
| 2 | 主体名 / 别名的文档检索 | 厂商规格页、检测报告这类正文资料 |
| 3 | **指标 + 数值**的跨主体检索 | 捞法规、标准、行业名录这类上位公共依据——它们不属于任何产品（语料里的民航规定 100Wh 上限就是），只按主体过滤会全部漏掉 |
| 4 | 站内同实体的其他说法（可选） | 交叉验证：同一商品的其他笔记怎么说 |

融合去重 → 相关度下限 →（有模型时）精排／判断。这样「漏关键内容」的风险被拆到「某一路没召回」，而每一路的召回率都能单独测——缺口任务的 `optimal_tools` 标注正是在测路径覆盖。

**为什么现在不做语义检索**：评测要离线可复跑、结果要能一步步复现，纯标准库实现了这两点；语义检索会同时破坏它们（还要联网或下载模型）。真实产品联网检索的入口在工具层（第四个工具 = 联网检索 + 结果快照），见 16 号文档 E4。
## 五、打分改造与主体过滤：实测（2026-10-14）

对 26 条标注主张逐条复算（脚本：`runs/tmp-vendor-base/score_probe.json`）。

**一、长度归一化 + 实体加权不改可分性。** 把打分改成"词面总分 ÷ (1 + log(1 + 文档长度))"，并把命中主体词的材料乘 1.5：可分条数 19/26 → 19/26，一条都没多。所以"先改打分函数再定阈值"里的这半步，实测**不是瓶颈**，不应作为下一步。

**二、真正的缺口是召回路径，不是分数。** 关键证据未被词面召回的 6 条里：

- 5 条（GAP-006/007/017/018/019）的标注关键证据**本身就是空集**——认证类主张在语料里没有对应的登记记录，这是已知缺陷"认证粒度太粗"的表现，不是检索问题；
- 1 条（GAP-003「可以带上飞机」，关键证据是民航规定 S-010）与主张字面完全没有重叠，必须靠第 3 路（指标＋数值跨主体）才能捞到。

**三、主体过滤确实会漏关键内容——用户提的这个问题成立。** 实测：按主体过滤后，GAP-003 的关键证据分从 2.00 掉到 0.00（民航规定不含主体词，被直接排除），其余条目可分性不变（19/21 → 19/21）。结论：主体只能作为一路召回，不能当唯一入口；并且**多路召回必须先于相关度下限**，否则第 3 路的材料会被下限与主体过滤双重误杀。

**四、唯一一条真被压过的案例本身是标注问题。** GAP-001「青禾 X1 续航 60 天」：关键证据标注写 S-001（厂商标称页，5.20 分），实际排第一的是 S-002（第三方检测报告，19.5 天，6.30 分）。打分把**更该被引用的那条**排在了前面。这条已在 19 号文档里作为标注缺陷记录在案，不构成打分的缺陷。

结论修正：**下一步不是调阈值，是把检索改造成多路召回**（第 3 路最关键），阈值只用于"证据是否充分"，不用于过滤召回结果。
