# 04 评测 Harness

## 它解决什么

这个 harness 把"Agent 到底做得好不好"变成可重复计算的数字，而不是看一次 Demo 的观感。它读 `data/eval_tasks.json`，调用指定的模型适配器，跑完指定管线，输出指标和逐案例失败明细。

## 两条被对比的管线

| 管线 | 做法 | 观察点 |
|---|---|---|
| v1 | 一次模型调用同时完成主张拆解和证据判定 | 便宜、快，但拆解与判定互相干扰 |
| v2 | 先拆解主张，再对每条主张单独做一次判定调用 | 调用次数增加，但单条判定上下文更干净 |

两条管线的输出结构一致，因此可以用完全相同的指标打分。比较 v1 和 v2 时模型必须固定，这是保证结论有效的前提。

## 指标定义

| 指标 | 定义 | 为什么重要 |
|---|---|---|
| 无依据确定性结论率 | 已给出判定的证据不足主张中，被判成 SUPPORTED 或 CONTRADICTED 的比例（没拆出来的、没给 verdict 字段的都**不进分母**，各自单列） | 这是核心指标。内容核查里最危险的错误是拿不确定当结论 |
| 主判定准确率 | 已匹配主张里四分类一致的比例 | 衡量判定方向是否正确 |
| 主张召回率 | 标注主张被拆出的比例 | 漏掉的主张不会被核查，等于没发现风险 |
| 主张精确率 | 拆出的主张中命中标注的比例 | 过度拆分会让复核队列变长 |
| 标志位召回率 | 过期、资料冲突、范围错配等标志的召回 | 标志位决定报告的解释质量 |
| 引用命中率（近似） | 引用编号与标注证据的重合度 | 只用于 v1／v2 评测；v3 用下一条代替 |
| 关键证据进结论率 | 标注的关键证据是否出现在**承载结论的来源**里（v3 的 `decided_by`） | 只检查"检索到过"会虚高：GAP-001 就是这么虚高的 |
| 判定字段缺失 | 输出里没有 verdict 字段的条数 | schema 崩坏不能被算成"最安全的答案" |
| 复核队列一致率（推导） | 是否该进人工复核队列的判断是否一致 | 由判定／标志位／主张类型推导，**不是独立指标**；不一致时按成因归因 |

## 错误分级

| 等级 | 定义 | 处理方式 |
|---|---|---|
| P0 | 影响内容处置方向，例如证据不足被判为支持 | 必须修复，直接决定版本能否上线 |
| P1 | 影响复核效率，例如标志位漏标、该进队列没进 | 优先修复 |
| P2 | 影响报告体验，例如引用定位不精确 | 迭代优化 |

## 指标的两个已知局限

**引用命中率是近似值。** 它只比较引用编号是否与标注一致，不能判断引用的那段文字是否真的支撑结论。要严格判定引用质量，需要引入人工评审或第二个模型做裁判，本期先不做。

**复核队列的标注来自规则推导。** `in_review_queue` 是依据 `docs/02-labeling-rules.md` 里的规则算出来的，不是独立的人工判断。因此这项指标衡量的是"规则有没有被正确执行"，不是"规则本身对不对"。实测更能说明问题：4 次历史运行里的不一致**全部**归因于"判定不同"，也就是说它没有带来独立信息——所以 2026-10-13 把它降级为推导指标，并加上成因归因。

**"引用命中率"只服务 v1／v2。** 那两条管线的输出里没有"哪个来源承载了结论"这个字段，所以只能做近似比对。v3 的运行时会给每条结论记下 `decided_by`，因此缺口评测用的是更严的"关键证据进结论率"：关键证据必须落在承载结论的来源里。

## 命令行

| 命令 | 用途 |
|---|---|
| `--validate-only` | 校验任务集结构、引用完整性和类别分布 |
| `--adapter stub` | 离线跑通管线，验证评测代码 |
| `--adapter deepseek` | 调真实模型，需要设置 `DEEPSEEK_API_KEY` |
| `--pipeline v1 / v2` | 选择被对比的管线 |
| `--limit N` | 先跑少量任务，验证 Prompt 再全量跑 |
| `--cases EV-007,EV-013` | 只跑指定案例，用于调试单条失败 |

## 输出物

每次运行在 `runs/<run_id>/` 下生成四个文件：

- `report.md`：给人看的评测报告，含指标、分案例结果和失败明细
- `results.json`：机器可读的完整结果，含每条主张的判定与标志位
- `trace.jsonl`：每次模型调用的输入、输出、耗时、token、重试和错误码
- `run_meta.json`：本次运行的配置快照，用于后续对比时确认变量
