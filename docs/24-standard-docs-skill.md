# 24 标准文档库与 skill 机制

> 建立时间：2026-10-14　|　缘起：用户指出「危险等级和容差不该放在同一份文档里」，并提出把标准文档与工作区分离。

## 一、问题

`docs/` 里的 22 号文档把「危害分级」与「容差」写在一起，原因只是它们回答的是同一轮提问。这类文档是按「回答过什么」组织的，不是按「属于哪一类规则」组织的，结果是可以引用的规则与讨论过程混在同一个目录里。

## 二、机制

新增 `文档库/`，与 `docs/` 分工：

| 目录 | 定位 | 收录内容 |
|---|---|---|
| `docs/` | 工作区。与用户的讨论与修改继续在这里进行 | 过程记录、实验数据、未决事项 |
| `文档库/` | 标准库 | 已定稿的规则、口径、架构与外部依据 |

- **同步时机**：关键改动／大版本变更，或周期性整理；不逐次同步；
- **内容要求**：只写当前生效的规则，陈述句，不出现第一人称、对话指代、思考过程、备选方案；
- **未决事项**留在 `docs/`；
- **依据状态**未落实的写「依据待补」，不得写成已核实。

分类固定六类：场景与定位、判定规则、评测口径、运行时与工具、处置与合规、调研与依据。首轮导入 8 份：项目定位与边界、主张抽取与标注规则、来源分级、容差、评测指标、处置档位、危害分级、检索架构依据。危害分级与容差因此被拆成两份文档，各自归档。

## 三、skill

Codex 只从全局 skills 目录发现 skill，项目级目录不被扫描。因此机制落成一个**全局 skill + 路径守卫**：

- 位置：`C:\Users\sFrank\.codex\skills\content-evidence-standard-docs\SKILL.md`；
- 描述里写明只在本项目目录内适用，其他项目与对话不适用；
- 项目内另加 `AGENTS.md` 声明「本项目默认使用该 skill」，使触发不依赖模型对描述的判断。
