# 26 内容风险研判工作台（可提交、可演示）

> 状态：**已完成**（2026-10-15）　|　缘起：Agent 页只能看历史产物，面试现场无法演示"输入内容 → 出结论"。
> 本文记这次改造的产品判断与实现口径。规则与档位口径没有改动，见 `文档库/05-处置与合规/`。

## 1. 改造前是什么

| 事实 | 证据 |
|---|---|
| 三个页面全部只读（除处置按钮） | `docs/15-workbench-v3.md:158` 自己列为已知局限 |
| 页面数据来自 `runs/` 下已有的评测产物 | `app/server.py` 的 `/api/queue` 读 `results.json` |
| 因此现场只能展示"上次跑完的样子"，不能演示"现在跑一次" | — |
| 界面也没有"内容级结论"的落点：队列是**主张级**的，而运营的工作单位是内容条 | `docs/11-scenario-validation.md` 第 4 节 |

结论：缺的不是视觉，是**一次真实运行的入口**与**内容级结论的呈现**。

## 2. 这一版做了什么

### 2.1 一条真实链路

```text
/workbench 粘贴内容
  → POST /api/run-content（服务端校验：空／超长／非法运行编号）
  → runtime/workbench.run_content
       runtime.extract_claim_texts 拆主张（规则，不读标注）
       EvidenceAgent.run_content   检索 + 充分性判定 + 判定 + 处置档位
       TraceWriter                 写 runs/<run_id>/trace.jsonl
  → 摊平成界面载荷（来源编号换成标题、维度与结构化取值）
  → 落盘 results.json / run_meta.json / report.md（与评测同格式）
```

关键选择：**产物格式与评测一致**。因此 `/api/queue`、`compare_agent_runs`、`rescore` 不需要为界面改一行；两类运行靠 `content_run` 标记互相拒绝（见 §4）。

### 2.2 页面结构

| 区域 | 内容 | 为什么这样排 |
|---|---|---|
| 顶部导航 | 内容研判 / 待复核队列 / 评测与版本 / 工具与语料 + 判定方式与语料状态 | 四个入口各自回答一个问题；顶栏状态只写有真实依据的字段（判定方式、语料版本与份数） |
| 左栏 | 最近研判（读真实产物） | 运营要能翻回上一次的结论 |
| 主区第一块 | 输入框 + 字数校验 + 演示样例 | 这是唯一的主操作，视觉上必须第一眼可见 |
| 主区 | 运行状态 | 同步调用，只有"正在研判"，**不编造分阶段进度** |
| 结果第一层 | 内容级摘要（分诊一句话 + 六格 + 需优先关注） | 运营的工作单位是内容条 |
| 结果第二层 | 逐条主张卡片（判定／理由／标志位／建议档位） | 主张是证据链的单位 |
| 结果第三层 | 证据包（承载结论的来源 / 仅被检索到的材料 / 数值偏差） | **检索到 ≠ 已证明**，必须分栏 |
| 结果第四层 | 规则依据（规则号、E/V/H 三维、下一步） | 让读者看懂"为什么是这个档位" |
| 折叠区 | 检索过程（每步选什么工具、为什么、结果、之后是否充分） | 需要时才展开，默认不占注意力 |

### 2.3 视觉

浅色工作台：中性灰底 + 白卡片，深蓝 `#1d4e9c` 只用于主按钮、当前入口与聚焦态。
语义色只出现在三类地方：状态标签、处置档位色条、原文高亮片段。风险色按档位递进
（绿→琥珀→蓝→红），不做大面积铺色，不加装饰性图表与动画。

## 3. 与运行时的边界（这一版刻意没做的事）

| 没做 | 原因 |
|---|---|
| 页面上的"模型／规则"切换开关 | 换判定方式会改变结论，属于运行配置（`--adapter` / `EVIDENCE_AGENT_ADAPTER`），不是运营随手切的东西 |
| 假的分阶段进度条 | 后端是同步调用，没有阶段回调；编造进度就是编造事实 |
| 把"标记复核"写进 `reviews.jsonl` | 该文件是**待复核队列**的记录，写进去等于冒充后台业务状态。现在只写页内内存，刷新即失效，页面写明 |
| 内容级"独立判定" | 内容级建议只是取各主张风险最高的一档（`TIER_RISK`），页面上标注了这一点 |
| 近似字符串比对来标数值 | 主张文本是原文子串，所以直接用 `highlight.py` 算出的字符偏移标；偏差百分比用与 `assessor.TOLERANCE_BY_METRIC` 同一张容差表算，只作提示 |

## 4. 两类产物互相拒绝

| 位置 | 行为 | 理由 |
|---|---|---|
| `/api/agent-runs` | 不列内容研判运行 | 没有标注、没有任务集，混进版本对比会被当成评测运行比分数 |
| `load_agent_results` | 内容研判产物抛 `ValueError` | 同上，从数据层就断掉 |
| `/api/content-run` | 缺口评测运行抛 `ValueError` | 反向也要拒绝 |
| `classify_run` | 内容研判归为 `content` | 评测页的运行分类多一类，不落进 full/smoke/legacy |

## 5. 错误分类（界面据此给不同反馈）

| 情形 | HTTP | 界面表现 |
|---|---|---|
| 内容为空／超长 | 400 | 就地提示，标出超出的字数 |
| 运行编号非法 | 400 | 提示编号不合法（正常路径下由服务端生成，用户看不到） |
| 同一秒重复提交（目录冲突） | 409 | "稍等一秒再提交" + 重试按钮 |
| 判定方式不支持 | 400 | 提示允许的取值 |
| 模型判定但没配密钥 | **200 + 结构化 error** | "运行条件不足" + 明确指引，**不静默降级成规则结论** |
| 其他异常 | 500 | 中性描述（只回异常类型名），不带堆栈 |

请求体上限 64 KB（内容上限 4000 字），超限在读之前就拒绝。

## 7. 已知限制

1. 检索是**受控离线语料**（24 份资料 / 28 条事实），不是真实联网检索；演示时必须说明，否则会被误认为接了真实数据源；
2. 主张由**规则抽取器**拆，不是模型抽取（模型抽取的主张精确率实测 47%，见 `docs/25-handoff-20261015.md`）；
3. 实体与指标由规则推断，认错主体时会给出无关的结构化取值（页面上以"事实库记录"呈现，未做置信度区分）；
4. 复核标记只在页内内存，无持久化、无归属；
5. 运行编号精确到秒，同秒并发提交会 409（已做保护，但不排队）。
