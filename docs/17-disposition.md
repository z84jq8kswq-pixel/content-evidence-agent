# 17 处置档位

回答一个问题：**判断出"这条说法与事实不符"之后，平台该做什么。**

这一层是补上的缺口。在此之前，运行时只有三种终止状态（有结论／转人工／工具不可用），而我把 `JUDGED` 直接当成了"可放行"——那是偷懒。`JUDGED` 只表示有结论，不表示可以放行：一条被判 `CONTRADICTED` 的主张，可能只是无伤大雅的体验夸大，也可能涉及电池安全，结论一样，处置完全不同。

## 三个维度

| 维度 | 回答 | 取值 | 依据 |
|---|---|---|---|
| 证据强度 E | 能不能动 | E3 强／E2 中／E1 弱／E0 无 | 举证责任：做了对外动作就要拿得出证据 |
| 违规构成 V | 能怎么动 | V2 违规／V1 疑似／V0 无 | 平台规则文本 |
| 危害性质 H | 动多重 | H3 高／H2 中／H1 低 | 处置成本与可逆性 |

### 证据强度

| 取值 | 判定条件（直接由运行时现有输出算出） |
|---|---|
| E3 | 证据充分，且 ≥2 个互相独立的 A/B 级来源一致 |
| E2 | 证据充分，但只有 1 个 A/B 级来源，无交叉验证 |
| E1 | 不充分：只有 C/D、来源冲突、来源过期、检索用尽 |
| E0 | 工具失败，本次核查不成立 |

**E1 及以下是一道硬门槛：禁止一切对外动作。**这不是道德要求，是风控要求——平台一旦动手，创作者可以申诉、监管会要证据，举不出证据的处置在两边都输。

### 违规构成

前提是一条硬规则：**必须"被证伪"才可能构成违规。**

- `SUPPORTED` 与 `INSUFFICIENT` 一律 V0——真实的主张不构成虚假宣传，查不出结论的主张也不能被指控，否则就是拿不确定当罪名；
- `CONTRADICTED` 且内容带营销特征（推广／合作／素人／测评等）→ V2；
- `CONTRADICTED` 但无营销特征 → V1；`PARTIAL` → V1。

### 危害性质

`claim_type` 优先（`health_safety` 与 `certification` 直接判 H3），其次看词，最后默认 H2——本场景下的主张大多落在"影响消费决策"这一档。

H3 的词表包含安全、过热、爆炸、有毒、过敏、儿童、孕妇、药品、治疗、认证、资质、批准文号、额定能量、登机等。

## 规则表

顺序即优先级，**E → V → H 不能调换**。先看危害就会在没证据的时候动手，那是最危险的错误。

| 规则 | 条件 | 档位 |
|---|---|---|
| R1 | E0 | 转人工（系统不可用） |
| R2 | E1 且 H3 | 转人工，**优先级最高** |
| R3 | E1 | 转人工（禁止对外动作） |
| R4 | 结论为支持 | 放行 |
| R12 | 结论为证据不足但 E2/E3 | 转人工（证据够却给不出结论＝能力缺口） |
| R13 | 承载结论的来源全是厂商自述，且规则给出的是对外动作（降级分发／打标／转违规） | 转人工（依据不够独立） |
| R5 | V2 | 转违规处置 |
| R6 | V1 且 H3 且 E3 | 打标提示读者 |
| R7 | V1 且 H3 且 E2 | 转人工（单一来源不足以支撑公开动作） |
| R8 | V1 且 H2 且 E3 | 降级分发 + 通知创作者 |
| R9 | V1 且 H2 且 E2 | 转人工 |
| R10 | V1 且 H1 | 通知创作者整改 |
| R11 | 其余 | 转人工（兜底，保守） |

两条设计约束写进了代码注释，值得单独强调：

**一、这是门槛制 + 梯度，不是加权打分。**如果做成评分制（证据 40% + 危害 40% + 违规 20%），"证据不足但危害极大"会被平均成一个中等分然后放行。所以 E 是开关，开关不参与加权。

**二、规则不匹配时保守转人工。**兜底分支永远倒向"交给人"，不倒向"动手"。

## 档位

| 档位 | 说明 | 需要人 | 风险 |
|---|---|---|---|
| 放行 | 不改动，仅入库为判例 | 否 | 0 |
| 降级分发 | 不进推荐池／搜索降权，用户无感 | 否 | 2 |
| 打标提示读者 | 在内容上标注该说法未经验证 | 否 | 3 |
| 通知创作者整改 | 给作者发提示，修改后可恢复 | 否 | 4 |
| 转违规处置 | 下架／账号级，须走违规流程并支持申诉 | 是 | 5 |
| 转人工 | 证据不足，不做任何对外动作 | 是 | 1 |

**入库为判例不占按钮位**——它每次都自动发生。同一商品被核查过三次，第四次就不该从零开始。

## 评测

八条缺口主张（GAP-003 补了"可以带上飞机"）都加了 `expected_tier` 标注，评测报告新增「档位准确率」并逐条显示建议档位：

```text
| 档位准确率 | 100% |

| GAP-001 | 数值夸大 | 青禾 X1 续航 60 天 | downrank ✅ | lookup_fact |
| GAP-002 | 过时认证 | 获得口腔护理协会认证 | manual ✅ | lookup_fact |
| GAP-003 | 来源冲突 | 云石 P20 额定能量 74Wh | manual ✅ | lookup_fact |
| GAP-004 | 只有低等级来源 | 云石 P20 有电池过热隐患 | manual ✅ | search_notes |
| GAP-005 | 零资料 | 云石 P20 容量 20000mAh | release ✅ | lookup_fact |
| GAP-006 | 检索不到 | 莱茵 H9 滤芯寿命 3 年 | manual ✅ | search_notes ×2 |
| GAP-007 | 指标粒度 | 通过了欧盟 CE 认证 | manual ✅ | lookup_fact |
| GAP-003 | 来源冲突 | 可以带上飞机 | release ✅ | lookup_fact（阈值比对） |
```

**这套规则不是我为了凑合现状编的**：先按框架推出每条应该去哪一档，再跑，再对。七条里六条与系统原有行为一致，只有 GAP-001 变了——原本直接放行，按框架应该是"降级分发 + 通知创作者整改"。这正是补这一层的意义：**它抓出了一个真实的漏判。**

顺带也抓出规则表本来缺一条：GAP-004 是"证据充足但系统给不出结论"（规则判不了又没配模型），落进了兜底分支。补了 R12，理由写明是能力缺口而不是判断结果。

## 许可型主张的阈值比对

有一类主张问的不是"这个数值是多少"，而是"这个数值有没有越过规定"——比如"可以带上飞机"。它没有数值可比，也不是排他词，原来的规则完全接不住。

补的做法是**把法规阈值也存成事实**：

```text
{"entity": "民航规定", "metric": "可随身携带额定能量上限",
 "value": 100, "unit": "Wh", "source_id": "S-007", "tier": "A"}
```

`compare_permission` 取主体的指标值，与限额比对。目前只有一条规则（登机额定能量），词表驱动，**不是通用推理**。

这一条带来一个反直觉的结论：**阈值判定能吸收来源冲突。**74Wh 与 62Wh 虽然互相矛盾，但都落在 100Wh 以内，所以"可以带上飞机"仍然成立。为此加了显式的 `evidence_override`——判定说结论成立，档位就不该再按"证据不足"算，但调用方必须写明为什么覆盖。

代价是这条主张的 `SOURCE_CONFLICT` 标志被摘掉了：冲突确实存在，但已被吸收，继续挂着会误导读者；理由里保留了"62Wh/74Wh 都未超限"的完整说明。

顺带补了两个支撑问题：

- **检索够不到法规文档。**正文写的是"乘机""可随身携带"，用户说的是"带上飞机"，字面检索命不中。语料文档因此增加 `keywords` 字段（同义说法），检索时按标题同等权重参与打分。
- **同一单位不等于同一指标。**高亮原来只按单位过滤事实，把民航那条"上限 100Wh"当成了分歧的一方，于是 74Wh 被标红。现在按"离这个数值最近的指标词"取指标，一句话里的两个数值各归各位。

还揪出一处一致性 bug：74Wh 被判成"与最权威来源不一致"，而判定却说"来源冲突"。根因是高亮取最权威值时，**等级相同的情况下取了更旧的日期**（运行时的 `compare_numeric` 取的是更新的那条，两处口径不一致）。已统一为"先看等级，等级相同取更新"。可信来源之间本身打架时，现在标成第三种状态「可信来源不一致」，而不是硬说这个数值对或错。

## 界面上怎么体现

- 队列行不再显示"调用 N 次"这类内部诊断，改显示建议档位；
- 判断结果卡里加一行「建议处置 + 依据」，把 E／V／H 和触发的规则号摊开——**可解释性不能只写在文档里**；
- 处置按钮换成六个档位，按风险从低到高排列，颜色即风险；
- 「转违规处置」二次确认（对创作者有实际影响且需要证据链）；
- 免责声明从每条详情里移到页头，只说一次。

## 已知局限

1. **H 的词表是举例，不是清单。**"涉及健康安全"具体包含哪些品类，落地时要按平台的实际品类体系列全。
2. **营销特征靠关键词识别**，会漏（隐晦的软广）也会过（正常提到"测评"）。真实系统应结合账号商业关系数据。
3. **档位是建议，不是审批流。**真实平台里"打标"和"下架"通常不是同一个角色能点的，本期没有权限差异，只在界面上用二次确认做了最小提示。
4. ~~E3 的"互相独立"只按 source_id 判~~ —— 已改为按**发布者**去重（同一家机构的两次检测只算一个来源）。但仍未判断"两份材料是否同源"的更深情形，例如同一份报告被两家媒体转载、其中一家挂了不同署名。

## 测试

`tests/test_disposition.py` 共 28 个用例：三个维度的取值、每条规则的触发、顺序不可颠倒（证据不足时危害再大也不能动手）、兜底保守、以及分布统计。加上许可型比对（`tests/test_runtime.py`）与高亮口径（`tests/test_highlight.py`，24 个用例）的新增覆盖，全套 **192 个测试通过**。

## 来源类型进入档位判定（R13，2026-10-14）

处置的依据要经得起申诉与监管：平台一旦做对外动作，就要拿得出可以摆到台面上的独立依据，而厂商自述只能证明"厂商是这么说的"，不能证明"事实如此"。因此新增一条门槛：**承载结论的来源全部是厂商自述时，降级分发／打标／转违规三档一律不触发，改写为转人工（R13）**。

两处边界：

- **通知创作者整改（R10）不受限制**。它面向创作者本人，不改变内容的分发与公开展示；
- **结论本身照常给出**，照样写进报告（"与厂商标称一致／不一致"），被拦下的只是动作。这对应"责任类型的转换，不是免除"：平台不替厂商背书，也不因为厂商自述而加重处置。

判定读的是**承载结论的那几条来源**（`assessment.decisive_sources`），不是检索回来的整堆材料——抽屉里放着别人的检测报告、结论却只引了厂商自己的页面，仍然算"仅凭厂商自述"。

实测影响（26 条主张，规则路径）：改动前后逐项指标完全一致（`runs/tmp-vendor-base` 与 `runs/tmp-vendor-after2`，27 项指标差异 0 项）。现有任务集里没有任何一条处在对外档位的主张是仅凭厂商自述支撑的——唯一一条对外档位是 GAP-001「青禾 X1 续航 60 天」判降级分发（R8），依据是独立检测 S-002。所以 R13 今天是纯安全阀：零副作用，拦住的是"依据只有厂商自己那一页却去打标或下架"的情形。
