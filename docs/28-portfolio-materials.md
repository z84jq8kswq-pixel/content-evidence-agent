## 一、一句话 + 三个数字

**一句话**

> 为一类"看起来像事实、实际站不住脚"的消费决策内容，设计了一套**内容条级分诊**流程：
> 拆出主张 → 逐条检索证据 → 判断证据够不够支撑结论 → 给出处置档位，
> 把判得了的自动放行、判不了的连证据一起交回人工，并用可复现的评测持续验证它。

**三个数字**（都可以在仓库里复现）

| 数字 | 含义 | 出处 |
|---|---|---|
| **100%** | 分诊一致率：26 条主张"该不该交给人"全部判对 | `runs/tmp-vendor-after2/report.md`，`harness/run_agent_eval.py` 可复跑 |
| **46%** | 转人工率：一半以上交回人工，**不是"全自动"** | 同上 |
| **0.000** | 同一配置重复运行的噪声带（规则路径），模型判定路径 3.8 个点 | `harness/repeat_agent_eval.py` |

## 二、简历写法（两种长度，按空间选）

**两行版**

> **内容证据核查 Agent**（个人项目，纯 Python 标准库 + 原生 JS，13,266 行代码、399 项单元测试）
> 针对消费类内容的事实性误导，设计"主张级证据链 + 内容条级分诊"流程：拆主张→检索→充分性判定→处置档位（R1–R13）。
> 自建 19 条缺口任务 + 30 条评测任务，实测分诊一致率 100%、转人工率 46%、重复运行噪声带 0.000。

**四行版**（推荐，把产品判断也写进去）

> **内容证据核查 Agent**（个人项目｜纯 Python 标准库，无第三方依赖｜13,266 行 + 399 项测试）
> - **定位修正**：公开资料验证后发现"运营逐条核查事实"这个前提不成立（运营的工作单位是内容条、按规则表高速判断），据
>   此把产品从"查证工具"改成"**内容条级分诊 + 主张级证据链**"，并主动更正了对竞品的误判。
> - **规则设计**：把"结论"与"动作"拆开，用 证据强度 E × 违规构成 V × 危害性质 H 的门槛制（R1–R13）决定处置；
>   关键判断是"必须被证伪才可能构成违规"和"仅凭厂商自述不得触发对外动作"（举证责任）。
> - **可评测**：自建 19 条缺口任务 / 30 条评测任务，定义"无依据确定性结论率"作为核心指标；同配置重复运行噪声带 **0.000**。
> - **实测**：分诊一致率 **100%**，转人工率 **46%**（把不确定性交回人，而不是硬给结论）。

**一句话数字要说清口径**（避免被追问时翻车）
- 这些是**规则路径在自建任务集上**的结果，不是生产准确率；
- 换真实模型后状态一致率降到 **87.5%**，主张抽取精确率只有 **47%**——我会主动说这一条。

## 三、五分钟演示脚本

**准备**：`python app/server.py --port 8788` → 打开 `http://127.0.0.1:8788/workbench`

| 时间 | 动作 | 要讲的一句话 |
|---|---|---|
| 0:00–0:30 | 打开页面，指顶栏 | "判定方式写在这里：规则路径离线可复现，换模型判定要另配。**结论只来自这次运行**，页面上没有预制结果。" |
| 0:30–1:00 | 点「载入样例：GAP-008 长句多判断」→「开始研判」 | "一句话里三个可核查判断，系统按子句拆开逐条判。" |
| 1:00–2:00 | 看内容级摘要 | "运营的工作单位是**内容条**，所以第一屏给的是分诊结论：几条给出结论、几条要人看、有没有系统不可用。最后那格是处置建议，取自各条里最高档。" |
| 2:00–3:00 | 展开一条"支持"的主张 → 证据包 | "这里区分**承载结论的来源**和**仅被检索到的材料**——检索到不等于已证明。这是这个项目最重要的一个设计决定。" |
| 3:00–3:45 | 展开"查看检索过程" | "每一步都记了**为什么选这个工具**，不是只记调用了什么。失败也留痕：换策略、降级都会标出来。" |
| 3:45–4:30 | 看一条"冲突"主张的规则依据 | "判定是 CONTRADICTED，但档位是 **R9 转人工**而不是直接下架——因为只有单一来源支撑，不足以做对外动作。这是举证责任。" |
| 4:30–5:00 | 切到「评测与版本」页 | "这些都靠评测撑着：自建 19 条缺口任务，同配置重复跑噪声带 0.000，指标不变才敢说改动有效。" |

**如果面试官问"能联网吗"**：答"能取真实网页，但**只作人工参考、不参与判定**——联网材料没有来源身份与资质字段，直接进判定会让分级失效。评测基线保持离线可复现，这是刻意取舍。"

## 四、高频追问与答法

| 追问 | 怎么答（要点 + 出处） |
|---|---|
| 你这套指标是不是自己出的题自己判？ | "是自建的，所以我在 README 首屏就写了'不是生产准确率'。19 条任务、其中 12 条标注由 AI 起草且**尚待人工复查**，也没有 holdout 集——这些我都写在已知限制里。" |
| 100% 是不是过拟合？ | "规则路径的 100% 确实有过拟合风险，因为任务集是我造的、规则是我照着它调的。所以我另外跑了真实模型基线：状态一致率 **87.5%**，主张抽取精确率 **47%**。真实条件下的短板我写在 `docs/25`。" |
| 为什么不用大模型直接判？ | "规则优先、模型补位。规则判不了才叫模型，而且模型只在**已检索到的证据包**上判断，不决定去哪查。理由是成本与可复现性：规则路径噪声带 0.000，模型路径 3.8 个点、每次约 0.003 元。" |
| 转人工率 46% 是不是太高？ | "我认为这是**诚实**的表现而不是缺陷：26 条主张里 12 条证据本身不足或互相冲突。核心指标是'无依据确定性结论率'——宁可交人，不能拿不确定当结论。而且其中一部分是语料里认证登记记录缺失导致的，属于已知缺陷。" |
| 为什么定位从"查证"改成分诊？ | "我先做了场景验证，写死了证伪标准再去找证据，结果 Q3/Q5 没被支持：运营的真实工作单位是内容条、按规则表高速判断，不做逐条核查。所以定位改了，并且更正的还有对腾讯较真的误判——在'查得准'上这个项目不可能超过它。" |
| 处置档位为什么不用评分制？ | "评分制会把'证据不足但危害极大'平均成一个中等分然后放行——那是最危险的错误。所以是门槛制 + 梯度，顺序 E → V → H，规则不匹配时保守转人工。" |
| 你怎么证明改动是有效的？ | "先建基线再改，逐项对照。比如来源分级重构那次：24 份语料重算 + 26 条缺口任务逐条对照，确认指标**逐项零变化**才提交。方法是 `harness/snapshot_grading.py --diff before after`。" |
| 这个项目有什么已知缺陷？ | "两条有回归测试锁定：① 认证类主张的粒度太粗（语料里没有认证登记记录，只能判证据不足，还会误报 STALE）；② 同一主体的无关文档会被当证据（GAP-004）。第三条是真实的模型抽取精确率只有 47%。" |
| 如果上线你会先改什么？ | "检索层改多路召回。已经做过诊断：长度归一化与实体加权对可分性零改善（19/26→19/26），主体过滤反而会漏关键内容（GAP-003 关键证据分 2.00→0.00），所以瓶颈是召回路径而不是阈值。" |
| 商业上成立吗？ | "我做过调研，结论是**不成立**：关键词级合规检测已经被打到几十元一年，企业级内容风控的买方是平台和大模型厂商而不是品牌方，'主张级事实核查'找不到任何公开付费案例。所以我把它定位成平台内部工具，价值在可评测迭代。" |

## 五、不要说的话（守住可信度）

- ❌ "准确率 100%" → ✅ "在自建任务集上分诊一致率 100%，真实模型基线是 87.5%"
- ❌ "能自动审核内容" → ✅ "只给处置建议，动作不自动执行；判错了被投诉的是平台"
- ❌ "接了真实数据" → ✅ "证据来自受控离线语料，另有一个联网参考区但**不参与判定**"
- ❌ "节省 54% 人工" → ✅ "转人工率 46%；转人工率不等于人工工作量下降比例"
- ❌ "已上线/已在用" → ✅ "个人项目，没有真实用户；场景假设尚未做从业者访谈"
