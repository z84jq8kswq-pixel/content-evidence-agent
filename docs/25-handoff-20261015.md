## 一、项目是什么

内容证据核查 Agent（Content Evidence Agent）：面向内容运营与社区治理的**内容条级分诊**工具。输入一段消费决策类内容，拆出关键主张，逐条检索证据、判定「支持／部分支持／冲突／证据不足」，给出处置档位，并把高风险与不确定项交人工复核，输出可定位到原文与来源的结构化报告。

- 路径：`D:\JOB\项目\content-evidence-agent`（父目录名是中文「项目」）
- 技术栈：纯 Python 标准库 + 原生 JS，无第三方依赖；注释、文档、提交说明均用中文
- 默认模型：DeepSeek Flash，模型 id `deepseek-flash`，`https://api.deepseek.com/chat/completions`；温度 0

## 五、关键规则与数字

- **处置档位**：三维 E（证据强度）／V（违规构成）／H（危害性质），顺序 **E → V → H**，规则 R1–R13；形成门槛制加梯度，不是加权打分；不匹配时兜底转人工。`SUPPORTED` 走 R4 直接放行，H 不参与。
- **R13（2026-10-14 新增）**：承载结论的来源全部是厂商自述时，降级分发／打标／转违规三档一律改写为转人工；通知创作者不受限；结论照常给出。依据是举证责任——平台做对外动作要拿得出独立依据。
- **危害分级**：H3 高危词 32 个、H2 消费决策词 15 个、H1 主观体验词 7 个，另加 claim_type 映射（`health_safety`／`certification` 直接 H3）；判定顺序 **H3 → H2 → H1**；未命中默认 H2。词表**出处待补**（只有平台规则节选、法规条文、历史判例三类可用出处）。
- **来源分级**：主判据是门槛（`grading._eligibility`），权重只用于排序。取样方式与资质只在适用身份上计分；独立第三方的「厂商送检」不通过门槛。独立来源按**发布者**去重，发布者不明不计入。
- **容差**：标称型 5%、测量型 20%、比例型 10%、兜底 10%；「主张 vs 来源」的对比容差是 10%（`RELATIVE_CONFLICT_TOLERANCE`，在 `runtime/assessor.py`）。敏感性实测只压到「不能太紧」一侧，放宽那一侧缺案例。
- **三层检索工具**：`lookup_fact`（实体＋指标，唯一能被规则比对的）→ `search_notes`（中文二元组词面）→ `fetch_source`（取原文定位）；`max_rounds` = 3。

## 九、环境与操作约束（下一个 Agent 必读）

1. `apply_patch` 在本工作区**不可用**（报 "path contains a reparse point"）。改文件用 Python 脚本：读文件 → 断言锚点唯一 → 字符串替换 → `compile()` 校验 → 写 `.tmp` → `os.replace()`；
2. 写 `D:\JOB\项目` 内的文件可直接写；写项目外（如 `C:\Users\sFrank\.codex\skills`）需要 `sandbox_permissions: require_escalated`；
3. PowerShell 传中文与引号：用**单引号 here-string** `@'...'@ | Set-Content -Encoding UTF8`，双引号与反引号会原样保留；不要在命令行里放裸双引号拼接；
4. 控制台是 GBK：直接打印中文或 `✓` 会 `UnicodeEncodeError`，跑评测加 `--json` 或重定向输出；
5. `git` 已 `init -b main` 但**从未提交**；git 会报 dubious ownership，需要 `-c safe.directory=...`，建议用户执行一次 `git config --global --add safe.directory D:/JOB/项目/content-evidence-agent`；
6. 测试命令：`python -m unittest discover -s tests`（当前 268 项通过）。
