# 07 标注复查：把伪装成模型错误的标注缺陷找出来

## 为什么要复查

第一轮全量评测出现 3 个 P0 错误，看起来是模型在"证据不足"的案例上硬下结论。但在准备做推理预算实验时，我意识到一件事：**判定质量是拿标注当尺子量出来的，尺子本身有偏差的话，量出来的结论就不可信。**

所以先复查标注，再继续实验。

复查的方法很简单：把每条案例的内容、资料、标注并排读一遍，检查标注是否违反 `docs/02-labeling-rules.md` 里自己写的规则。不需要联网，因为这是闭世界评测集，所有证据都在文件里。

## 发现的问题

### 问题一：把内容里的绝对表述改写成带限定的版本

这是最严重的一类，也是最隐蔽的。标注时我把主张"修正"成了资料能支持的版本，而不是照抄内容里的说法。

EV-005 最典型：

- 内容写的是"数据**只存在本地** SD 卡，不上传云端"
- 我标注的主张却写成"小满监护器**默认**不上传云端，数据存于本地"
- 资料说的是"**默认**仅本地存储，云备份功能需用户手动开启"

标注把内容里没有的"默认"两个字加了进去，于是标注看起来能被资料完美支持，而内容实际表达的是一个绝对判断。按规则"主张省略了会改变结论的条件时判 PARTIAL"，正确标注应该是 PARTIAL 加 OMITTED_CONDITION，不是 SUPPORTED。

同类问题在 EV-001 上出现过一次，当时是把"续航 40 小时"标成 SUPPORTED，而同一套规则的 EV-025 把同样的表述标成 PARTIAL，两条自相矛盾。

**规律**：看到正面表述时，我会下意识地按"资料能支持什么"去写标注，而不是按"内容实际说了什么"去写。

### 问题二：标注违反自己的拆分规则

规则里写着"一条主张只包含一个可验证的核心判断，出现'而且''并且''同时'时通常要拆开"，但 EV-016 的标注写成了"该餐具可完全降解**且** 90 天降解完成"，一条标注里塞了两个判断。

模型把这条拆成了两条，我原本记为"多余主张"，实际上**模型的拆分才是符合规则的做法**。

### 问题三：内容里含未标注的第二条主张

有四条案例的内容里除了我标注的主张，还包含另一条可验证的描述，但我在标注时把它当成了"语气词"：

| 任务 | 内容里的第二条主张 | 处理 |
|---|---|---|
| EV-002 | 30 平客厅十几分钟就换一遍气 | 删除该从句，让案例聚焦单一主张 |
| EV-007 | 出门两天完全不用充电 | 删除该从句 |
| EV-009 | 别家做不出来 | 删除，它只是排他性的重复表述 |
| EV-025 | 出差一周都不用带充电器 | 删除该从句 |

模型把这些都正确地抽了出来，反倒被计成精确率损失。这是我的内容设计问题：要么标注它们，要么别把它们写进内容。我选择删掉，因为这几条案例的考察点不在拆解能力上。

### 问题四：标注本身存在指代歧义

EV-012 的内容是"澄野 C5 精华的烟酰胺浓度是 5%"，我标注为 INSUFFICIENT 加 SOURCE_CONFLICT，理由是官网当前页面写 3%、旧包装写 5%，无法确定所指版本。

但模型一直判 CONTRADICTED，而且这个判断是站得住的：内容没有限定版本，自然读法就是指当前在售产品，而官网当前数据是 3%，直接构成冲突。

**这条案例作为考题是有缺陷的**——两种读法都符合规则，说明题目本身没有唯一答案。修法是把内容改成明确指向当前版本："澄野 C5 精华现在的烟酰胺浓度还是 5%"，此时 CONTRADICTED 加 STALE 就是唯一合理的判定。

## 另外精简了两处标志位

EV-019 原来要求同时标 STALE 和 SCOPE_MISMATCH，但这条案例的核心只是"有现版本反证时判冲突"，SCOPE_MISMATCH 属于延伸推断，删掉。

EV-023 原来要求 STALE、SOURCE_CONFLICT、SCOPE_MISMATCH 三个标志，其中 SOURCE_CONFLICT 不成立——两份测评针对的是不同代次的产品，这不是资料互相矛盾，而是版本错配。删掉 SOURCE_CONFLICT。

EV-030 的第一条主张（IPX5 等级）原本容易被认为也该判 PARTIAL，我补充了说明：IPX5 是产品标注的防水等级，接口盖闭合是该等级定义的一部分，不算被省略的条件；真正的范围外推在第二条主张"下雨天可以放心使用"上。

## 复查后的结果

标注修订后重跑同一配置（抽取和判定都关闭思考），与修订前对比：

| 指标 | 修订前 | 修订后 |
|---|---|---|
| P0 错误 | 2 | **0** |
| 无依据确定性结论率 | 0.0909 | **0.0000** |
| 主判定准确率 | 0.7879 | **0.8857** |
| 主张召回率 | 0.9706 | **1.0000** |
| 标志位召回率 | 0.7097 | **0.7241** |

## 最重要的结论

P0 从 2 降到 0，但模型一个参数都没改。

也就是说，**那 2 个 P0 错误里有相当一部分是我的标注缺陷，而不是模型的判断错误**。评测集的错误会伪装成模型错误——它不会报错，只会安静地让指标变难看，然后你会去改模型，改错了方向。

这件事的价值在于它验证了评测流程本身的必要性。如果只有一份 Prompt 和一份主观的"感觉还行"，这个错误永远不会被发现；正因为有逐条标注、有 P0/P1 分级、有和规则文档的交叉比对，问题才在第三次运行前被抓住。

写进作品集时，这一段比"MVP 跑通"更有说服力：它展示的是发现自己的尺子有问题，并且知道该先修尺子。
