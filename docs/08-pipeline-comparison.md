# 08 管线对比：一次调用还是两段式

## 要回答的问题

v2 的流程是"先抽取主张，再对每条主张单独判定"，一条任务要发 1 次抽取加 N 次判定调用。v1 把两件事合并成一次调用。

直觉上 v1 更省：调用次数少一半以上，输入 token 也少得多，因为不用把资料重复发给每一条主张。问题是这样省，质量要付多少代价？这是运行时架构的典型取舍，值得用数据回答，而不是凭感觉选。

## 实验设计

为了只比较"架构"这一个变量，两组配置在模型侧完全一致：同一个模型、同一个温度、都关闭思考模式。差异只有一处：

| 配置 | 单任务调用次数 | 说明 |
|---|---|---|
| v1 | 1 次 | 一次输出全部主张及其判定 |
| v2 | 1 + N 次 | 先抽取，再逐条判定 |

任务集、提示词内容、匹配阈值、计费时段全部相同。

## 结果

| 指标 | v1 单次调用 | v2 两段式 | 变化 |
|---|---|---|---|
| 主判定准确率 | 0.7429 | **0.8857** | +0.1428 |
| 主张精确率 | 0.8974 | **0.9722** | +0.0748 |
| 无依据确定性结论率 | 0.0833 | **0.0000** | −0.0833 |
| P0 错误 | 1 | **0** | −1 |
| P1 错误 | 18 | **11** | −7 |
| 主张召回率 | 1.0000 | 1.0000 | 持平 |
| 标志位召回率 | 0.7241 | 0.7241 | 持平 |
| 复核队列一致率 | 0.9429 | 0.9429 | 持平 |
| 模型调用次数 | **30** | 66 | +36 |
| 输入 token | **18,630** | 34,866 | +16,236 |
| 输出 token | 4,402 | **3,502** | −900 |
| 平均单任务耗时 | **1,561 ms** | 2,657 ms | +1,096 |
| 估算成本（30 条） | **0.0362 元** | 0.0489 元 | +0.0126 |

## 怎么读

v2 在全部质量指标上更好或持平，其中主判定准确率高出 14 个百分点，并且把 P0 清零。

v1 省下的是调用次数和输入 token，但折算成钱只省了 0.0126 元——**用 1.3 分钱换 14 个百分点的判定准确率**。这笔账不需要犹豫。

值得注意的是输出 token：v2 反而比 v1 少。原因是 v1 要在一次回复里同时输出全部主张、全部判定和全部理由，单次回复很长；v2 的每次判定只需要输出一条主张的结论。所以 v1 省的是输入，不是输出。

## 具体差在哪

两组之间 7 条案例判定不同，6 条 v2 正确、1 条 v1 正确：

| 任务 | 期望 | v1 | v2 | 结果 |
|---|---|---|---|---|
| EV-006 滚刷拆卸水洗 | SUPPORTED | PARTIAL | SUPPORTED | v2 正确 |
| EV-010 认证编号错配 | CONTRADICTED | INSUFFICIENT | CONTRADICTED | v2 正确 |
| EV-020 旧促销价 | CONTRADICTED | INSUFFICIENT | CONTRADICTED | v2 正确 |
| EV-022 认证过期 | INSUFFICIENT | CONTRADICTED | INSUFFICIENT | v2 正确 |
| EV-023 换代评测数据 | INSUFFICIENT | PARTIAL | INSUFFICIENT | v2 正确 |
| EV-027 小样本效果 | PARTIAL | INSUFFICIENT | PARTIAL | v2 正确 |
| EV-030 IPX5 等级 | SUPPORTED | SUPPORTED | INSUFFICIENT | v1 正确 |

v1 唯一的 P0 是 EV-022：认证过了有效期，正确做法是判"证据不足 + 资料过期"，v1 判成了冲突。这又是那个反复出现的纪律问题——**把证据失效误当成证据反对**。

从错误模式看，v1 的偏差方向是"往中间挤"：该判冲突的判成证据不足，该判证据不足的判成冲突或部分支持。它在一次调用里要同时兼顾拆解和判定两件事，判定的注意力被摊薄了。v2 的每次判定只面对一条主张和一组资料，上下文干净得多。

## 这个差异是不是噪声

根据 `docs/06-reasoning-budget-experiment.md` 里的可复现性验证，两次运行之间一到两条案例的差异属于噪声。这里是 5 条主张的判定差异加 7 条 P1 差异，方向一致（6 比 1），明显超出噪声范围。

## 结论

默认保留 v2 两段式。

v1 并非没有价值。它的调用次数少一半以上，如果任务量很大、或者场景对准确率的要求没那么高（比如先做粗筛，再对可疑项做精细判定），v1 是合理的降本手段。这正好是平台该提供的选项——**两种运行时架构都保留，由使用者按场景选择**，而不是替他们写死一种。

这条对比也说明了评测 harness 的意义：如果没有逐条标注和指标，v1 和 v2 的差别在人工试用的观感上几乎看不出来，两者都能"跑出像样的报告"。
