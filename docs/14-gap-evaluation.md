# 14 缺口任务评测

对应 `10-prd-agent-v3.md` 第 6 节，是第 2 周的前半段。工具层和运行时解决"能不能自主检索"，这一层解决**"值不值得"**——用可复现的数字回答 v3 相对 v2 的增益与代价。

## 与现有评测的分工

| | `metrics.py`（原有） | `gap_eval.py`（本期） |
|---|---|---|
| 评什么 | 判定结果 | 判定结果 + **过程** |
| 任务集 | `data/eval_tasks.json`（30 条，资料齐全） | `data/gap_tasks.json`（19 条／26 条主张，资料有缺口；g3） |
| 关键问题 | 判得准不准 | 该查的查了吗、该交人的交了吗 |
| 主张从哪来 | 模型自己拆（v1 一次调用／v2 抽取阶段） | 系统自己拆（规则抽取器，**不读标注**） |

过程指标是本期新增的核心：一个 Agent 可能结论对了但路径全错（碰巧查到、查了 4 次才蒙对），只看结论看不出来。

## 缺口任务长什么样

每条任务给一段内容、一份**不完整的**用户资料，标注里除期望结论外还有**最优工具集**：

```json
{
  "id": "GAP-002",
  "given_sources": ["S-006"],
  "expected_claims": [{
    "text": "获得口腔护理协会认证",
    "expected_state": "ESCALATED",
    "flags": ["STALE"],
    "evidence": ["S-005", "S-006"],
    "optimal_tools": ["lookup_fact"],
    "reason_contains": "过期"
  }]
}
```

注意 `reason_contains` 这个字段：**只检查结论对不对是不够的**，还要检查转人工的**理由**对不对。"因为过期转人工"和"因为查不到转人工"是两件事，前者说明系统理解了时间维度，后者说明它只是没找到。

七条任务分别压不同的能力：

| 案例 | 类别 | 压的是什么 |
|---|---|---|
| GAP-001 | 数值夸大 | 只有带货文案时能不能找到厂商标称 |
| GAP-002 | 过时认证 | 分清"过期"与"查不到" |
| GAP-003 | 来源冲突 | 厂商标称与第三方实测相差 16% |
| GAP-004 | 只有低等级来源 | 只有匿名帖时明确说证据不足 |
| GAP-005 | 零资料 | 用户什么都不给，完全依赖检索 |
| GAP-006 | 检索不到 | 换策略后仍查不到，不许猜结论 |
| GAP-007 | 指标粒度 | 主张里的认证与事实库里的不是同一个 |

## v2 上界：为什么不用"跑一次真模型比分数"

v2 的证据来源被限定在用户给的资料里，所以在缺口任务上它有一个**先验天花板**：期望证据不在给定资料里的主张，v2 哪怕模型再强也够不着。

口径：期望能给出结论的主张里，期望证据全部在用户资料中的比例。这是**对 v2 最有利**的假设——假设它判断全对，只衡量它拿不到关键证据这一件事。

用上界而不是真模型跑分，有三个好处：不需要 API 预算；结果不受模型随机性影响；对照的结论更硬——"即便 v2 判断全对，它也够不着"比"v2 这次没跑好"难反驳得多。

### 证据口径改了什么（2026-10-13）

原来这条比的是"检索到的整堆材料里有没有标注的关键证据"，碰到过就算命中，所以是 100%。
现在运行时会给每条结论记下**承载它的来源**（`ClaimOutcome.decided_by`），指标只认这一份。
8 条标注主张里 6 条有明确的关键证据，命中 4 条：GAP-001 的结论由 S-002（第三方 19.5 天）承载，
标注的关键证据是 S-001（厂商标称 21 天）；GAP-004 的结论由 S-007（监管文档）顶成"证据充分"，
标注的关键证据是低等级帖 S-012。这两个洞在旧口径下是看不见的——它们正好对应本项目最想避免的
两种错误：用错基准、被无关的权威文档顶成有结论。

这张表就是项目最核心的那句结论：**在资料有缺口时，v2 的天花板是零，v3 能到 100%——代价是 62% 的主张需要人工介入。**

| 运行 | 主张来源 | 共有的 17 项指标 |
|---|---|---|
| `runs/gap-baseline` | 标注主张（oracle） | 基线 |
| `runs/gap-no-oracle` | 规则抽取（现在） | **逐项相同** |

结论写得直白一点：**之前的运行时指标没有被 oracle 抬高**——在 7 条缺口任务上，规则抽取器
把 8 条标注主张全部拆了出来，粒度也对得上（GAP-003 的一句话拆成两条）。这既是好消息，
也是这份对照的局限：任务集太短，抽取粒度的问题不容易暴露。真要让抽取能力被评测压到，
得加长句、多主张、带指代的内容。

## 基线里的三条失败明细

报告第六节会把它们逐条列出来。都不是意外，而是设计缺口：

| 案例 | 问题 | 性质 |
|---|---|---|
| GAP-004 | 理由说成"证据充分但规则无法判定"，实际应该是"证据不足" | 检索没有相关性阈值（`13-runtime.md` 已知局限 1） |
| GAP-007 | 把"欧盟 CE 认证"误判为"口腔护理协会认证过期"，误报 `STALE` | "认证"指标粒度太粗（已知局限 2） |
| GAP-006 | 首次评测报告的理由是"证据充分"，而非"检索用尽" | **本期新发现**：`2024 年 12 月` 里的单字"年"被当成检索词，导致任何提到年份的资料都算命中。已修：单个汉字不再作为检索词 |
| GAP-001、GAP-003 | 各多拆出 1 条主张：`云石 P20 充电宝容量 20000mAh`、`20000mAh 大容量` | **去掉 oracle 后新暴露**：两条都是内容里真实存在、可核查的说法，标注没标。属于任务集的标注缺口（同 07 号文档问题三），不是运行时错误 |

第三条值得记一下过程：它是在写缺口任务时暴露的，而不是在单元测试里。**单元测试测的是"实现符合预期"，缺口任务测的是"预期本身对不对"**——所以它才能找到测试写不出来的问题。

前两条我仍然**故意不修**：它们的解法都需要一个数字（相关性阈值、指标拆分粒度），而现在没有数据能告诉我这个数字该是多少。缺口任务的存在意义正是——等任务集扩到 20 条以上，再用数据定阈值，并且能验证修完之后指标是否真的动了。

模型判定这一步只改动了一条主张（GAP-004），但改动值得逐字看：

```text
规则判定：ESCALATED  证据充分但规则无法判定，需要模型或人工        decided_by=S-007
模型判定：JUDGED     唯一相关来源S-012为D级不可溯源传闻，仅称据说有电池过热隐患，不足以支撑该主张  decided_by=S-012
      处置档位：转人工（两条完全一样）
```

模型给出的判断在实质上是对的：它认出了唯一相关的来源是 D 级传闻，明确说不足以支撑该主张，
处置档位也没变（仍转人工）——而 `state` 这一栏把它记成状态错误。

**这条暴露的是指标口径问题，不是模型问题**，两处当天就修了：

1. 新增**分诊一致率**：按处置档位（`needs_human`）评"该交给人的有没有交到人手里"，
   而不是按原始 `state`。上面三组都是 100%——模型那组动作全对，掉下去的 12.5%
   只是"结论类型更细"的差异。原始 state 仍保留在同一张表里，供排查用。
2. GAP-004 的标注补上 `LOW_SOURCE_QUALITY`（按 02 号文档，D 级匿名来源必标）。补之前
   模型标它算"误报"（标志位查准 88% → 75%），补之后规则层的漏标才显出来：
   **标志位召回 规则 67% ／ 模型 100%**——规则层判"证据充分"用的是最权威的 S-007，
   根本没把 S-012 当证据，自然标不出"来源质量低"。

模型抽取（第三列）：召回仍是 100%，精确率 80% → 47%。多拆的 9 条里两类为主：

- 主观句被当成主张："青禾 X1 电动牙刷续航表现不错。""青禾 X1 电动牙刷刷牙震感舒服。"；
- 同一判断重复输出："青禾 X1 电动牙刷续航为 60 天" 与标注里那条并存；"云石 P20 充电宝容量为 20000mAh" 在两条内容里各出一次。

也有几条是**内容里真实存在、标注没标**的（"建议先别买…""符合欧洲标准""换芯频率低"），
性质同上一条标注缺陷。结论：在这 7 条短内容上，规则抽取器比模型抽取**更精确**，
而且便宜 12 倍；要判断模型抽取是否更好，得先有能压住"主观句"与"重复表述"的内容。

三个真缺陷都是扩样逼出来的，当天修掉并加了回归用例：

1. **抽取器丢比例型数值**：`废水比 1:1` 既没有"数字+单位"也没有断言词，整条被丢。修：把比例写法纳入可核查信号。
2. **跨实体串味**：冲突／过期判定以前只看指标不看实体，别的产品的同指标记录会参与。修：检索带回的结构化事实只在**实体和指标都认得出来且对得上**时才参与。
3. **证据包按主体收敛**：`证据充分` 以前算的是整堆检索结果，混进来的别的产品文档会让强度虚高。修：`assess` 只保留`在说这条主张主体`的证据（结构化事实按实体判，普通文本按正文里有没有出现主体名判）。这是"检索没有相关性门槛"的**实体版本**：可判、可测、不需要新阈值。
   顺带修了同源问题：`compare_numeric` 以前只按单位找对比目标，`续航 40 小时` 会被拿去比 `降噪续航 28 小时`。

4. **比例型指标没有比对路径**：抽取修好之后，规则层仍然只认数字+单位（`废水比 1:1` 这种写法抽不出数值），于是这类主张永远只能转人工。修：比例归一成 第一项/第二项、单位记 `:1`，并补上废水比这一行事实（2026-10-14）。

## 局限

1. **19 条／26 条主张，仍然偏小。**同配置重跑的噪声下限约 13% 的案例会翻转（见 06 号文档补记），所以 10 个点以内的改动测不出来；主张级指标（尤其标志位，只有 7 条带标志）比内容条级更吃样本。
2. **缺口任务是人工构造的**，语料也是构造的，不能用来推断真实场景的实际效果。**2026-10-13 起新增的 12 条由 AI 起草**（按 02 号文档的规则逐条推的判定），需要人工复查一遍再当基线用。
3. **离线跑的是规则判定**（规则判不了的主张不调用模型），所以"规则无法判定"这一类会偏多。真实模型基线已完成，见上一节：模型只把一条从转人工变成有结论，成本 0.0009 元；模型抽取的成本高 12 倍而精确率更低。
4. **时序成本只是代理**：`tool_calls` 和 `duration_ms` 不等于人工处理一条内容的真实耗时，后者需要真实用户才能测。
5. **抽取器在这 7 条上的召回是 100%，但那是因为内容都是短句。**它的已知局限（并列判断不拆、指代不消解）写在 `runtime/extract.py` 的模块注释里。

## 下一步

1. 缺口任务从 7 条扩到 20 条以上，把单案例权重压到 5% 以下；扩样时**专门加长句、多主张、带指代的内容**，否则抽取能力不会被压到；
2. 那 2 条多拆出来的主张：决定是补标注，还是明确写进规则允许（现在的精确率 80% 就是被它们拉下来的）；
3. 用真实模型跑一次（`--adapter deepseek`，可再加 `--extract model`），对比规则判定与模型判定的分工是否合理；
4. 有数据之后调相关性阈值与指标粒度，重跑同一套任务集验证指标变化。

## 测试

`tests/test_gap_eval.py` 共 27 个用例：任务集校验、打分口径（状态／判定／标志位／工具／理由）、按文本对齐（顺序无关、漏拆记 MISSING、多拆记 spurious）、上界计算，以及一组把基线指标锁住的端到端用例——指标一旦变化就会失败，逼着改动必须是有意的。

端到端用例**不再把标注主张喂给 Agent**：它和真实评测一样先跑规则抽取，所以抽取质量一变这些用例就会红。全套 233 个测试通过（评测 27、运行时 43、工具层 36、处置 30、原有 harness 27、高亮 24、来源等级 19、界面接口 17、抽取 6、运行目录 4）。
