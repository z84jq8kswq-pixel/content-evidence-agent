# 12 工具层

对应 `10-prd-agent-v3.md` 第 5.3／5.4 节，是第 1 周的前半段。目标不是做很多工具，而是让工具**可管理**：参数、超时、重试、降级、成本、留痕，六项齐全，才算 Tool Registry。

## 它解决什么

v2 的证据来源是人给的：资料随 Prompt 注入，模型没有"去找"这个动作。工具层补上的就是这一层——把"查资料"从模型的一次生成变成一次有规格、有预算、有记录的外部调用。

## 文件

| 文件 | 作用 |
|---|---|
| `src/evidence_agent/tools/base.py` | ToolSpec、ToolResult、Evidence、参数校验 |
| `src/evidence_agent/tools/registry.py` | 注册中心：校验、超时、重试、预算、调用记录 |
| `src/evidence_agent/tools/corpus.py` | 受控离线语料与检索 |
| `src/evidence_agent/tools/builtin.py` | 三个内置工具 |
| `data/corpus/sources.json` | 12 条资料，含过时、冲突与低等级内容 |
| `data/corpus/facts.json` | 11 条结构化事实，含同一指标的两条冲突记录 |

## 三个工具

超时、重试与降级路径与 PRD 逐字对齐，测试里直接断言这三项。

| 工具 | 超时 | 重试 | 降级 | 说明 |
|---|---|---|---|---|
| `search_notes` | 8s | 2 | `lookup_fact` | 关键词检索，标题命中权重加倍 |
| `lookup_fact` | 5s | 2 | 无（转人工） | 精确查询，查不到就是查不到 |
| `fetch_source` | 10s | 1 | 退回摘要 + `UNLOCATED_SPAN` | 定位失败不报错，标注降级 |

## 三态结果：OK / EMPTY / 错误

`EMPTY` 不是错误，它是运行时的重试触发条件。这个区分很关键：

- **工具层**只重试 `TIMEOUT` 与 `UPSTREAM_ERROR`，原样再调一次；
- **换查询词、换工具、拆细主张**属于运行时策略，不在工具层做。

如果把空结果也当成工具层重试，等于用同一个查询问三遍，白花预算，而且掩盖了"该换策略了"这个信号。

## 预算：按主张，不是全局

单条主张最多 4 次调用、合计 30 秒（PRD 5.4）。因此 registry **默认不持有预算**，运行时必须为每条主张新建 `CallBudget` 并显式传入。

这条规则是烟测逼出来的：最初把一份预算当默认值共享给所有调用，结果第 5 次调用被饿死，而且**不报错**——只是结论开始依赖调用顺序。这类错误在单元测试里看不出来，只有跑真实调用才会暴露。

## 一次真实调用

认证类主张（需要核实有效期）走到的路径：

```text
lookup_fact(青禾 X1, 认证)  -> OK  查到两条：2023 年认证（有效期至 2024-12）、2025 年未列入名录
```

两条记录相隔 21 个月，是"新来源覆盖旧来源"，运行时据此判 `STALE` 并转人工。这就是"过时认证"的判定路径，也正是 v2 做不到的部分——v2 只能在给定的资料里找，找不到就会直接说"证据不足"，分不出"过期"和"没查到"的区别。

## 语料为什么故意包含坏数据

如果语料干净、每条都有权威答案，"自主检索"会退化成固定查找，v3 的叙事就不成立了（PRD 风险 U4）。所以语料里刻意放了三类东西：

- **过时**：2023 年认证名录（有效期已过）
- **冲突**：云石 P20 额定能量 74Wh（厂商标称）与 62Wh（第三方实测，偏差 16%）
- **过期**：青禾 X1 的 2023 年认证（有效期至 2024-12）与 2025 年名录"未列入"
- **低等级**：匿名帖、带货文、无测试条件的用户自述

## 已知局限（必须写清）

1. **超时是事后计时**：本地工具同步执行，无法真正中断，超时只是记账。接真实网络工具时必须换成可中断实现。
2. **检索是词频／二元组匹配**，不是语义检索。同义改写（"能用多久" vs "续航"）会漏。
3. **语料是构造数据**，不代表真实分布，因此不能用来推断真实场景中的效果。
4. 三个工具都是只读的；写入类工具（如回写复核结论）不在本期。

## 测试

`tests/test_tools.py` 共 34 个用例，覆盖参数校验、重试上限、空结果不重试、超时转换、预算隔离、别名归一、冲突行返回、降级路径与 PRD 规格一致性。全套 61 个测试通过（其余 27 个是原有的评测 harness 测试，未受影响）。
